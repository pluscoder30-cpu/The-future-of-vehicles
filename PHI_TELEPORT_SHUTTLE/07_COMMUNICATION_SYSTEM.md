# Communication System — Onboard and Quantum-Linked Communications

## 1. System Overview

The communication system provides:
1. Standard radio communication (voice, data)
2. Quantum-linked communication (instantaneous, fold-correlated)
3. Fold signature monitoring (detect other fold events)
4. Emergency beacon (SOS, distress)

### 2.3 Fold-Communicated Data

During fold transit, standard radio communication is interrupted. The communication system buffers all pending messages and transmits them after fold completion.

During fold transit, the fold-correlated communication system (see Section 3) provides real-time communication.

## 3. Quantum-Linked Communication

### 3.1 Principle

The quantum-linked communication system uses **entangled photon pairs** generated by the fold coils to establish instantaneous communication between the vehicle and the ground station. This is not FTL communication — it is fold-correlated communication that uses the fold bridge as a communication channel.

### 3.2 Specifications

| Parameter | Value |
|-----------|-------|
| Carrier | Entangled photon pairs |
| Entanglement source | Fold coil (phi-harmonic photon generation) |
| Wavelength | 1550 nm (telecom band) |
| Data rate | 1 Mbps |
| Range | Unlimited (within fold light-cone) |
| Latency | 0 ms (fold-correlated) |
| Security | Quantum key distribution (QKD) |

### 3.3 Entanglement Generation

The fold coils generate entangled photon pairs during fold formation. The entanglement is created by the phi-harmonic field structure:

```
|Ψ⟩ = (1/√2)(|H⟩|V⟩ + |V⟩|H⟩)
```

where |H⟩ and |V⟩ are horizontal and vertical polarization states.

The entanglement rate is:

```
R_entangle = N_coils × φ × 10⁶ ≈ 12 × 1.618 × 10⁶ ≈ 19.4 Mpairs/s
```

### 3.4 Communication Protocol

The quantum-linked communication system uses the following protocol:

```
1. Entanglement generation (during fold formation)
2. Key distribution (QKD, 100 kbps)
3. Data encryption (AES-256, key from QKD)
4. Data transmission (encrypted, 1 Mbps)
5. Key verification (after fold collapse)
```

### 3.5 Fold-Correlated Communication

During fold transit, the fold bridge serves as a communication channel. The vehicle can send and receive data through the fold bridge at the speed of light within the folded metric — which appears instantaneous from the external metric perspective.

## 4. Fold Signature Monitoring

### 4.1 Fold Detection

The communication system includes a **fold signature monitor** that detects fold events in the vicinity. This is used for:
- Avoiding fold conflicts (two vehicles folding to the same location)
- Detecting unauthorized fold events
- Monitoring fold field integrity

### 4.2 Fold Signature Characteristics

A fold event produces a characteristic signature:

```
Fold signature:
  Frequency: 100 kHz - 1 MHz
  Amplitude: Proportional to fold energy
  Duration: 3-8 seconds (fold duration)
  Polarization: Circular (fold handedness)
  Spatial pattern: Phi-harmonic (self-similar)
```

### 4.3 Fold Conflict Avoidance

If the fold signature monitor detects another fold event at the target location, the navigation system:
1. Waits for the other fold event to complete
2. Checks for residual fold signature
3. Verifies the target location is clear
4. Proceeds with fold initiation

## 5. Emergency Beacon

### 5.1 Beacon Specifications

| Parameter | Value |
|-----------|-------|
| Frequency | 121.5 MHz (emergency) |
| Frequency | 406 MHz (EPIRB) |
| Power | 10 W |
| Range | 300 km (line-of-sight) |
| Modulation | AM tone (121.5 MHz), digital (406 MHz) |
| Activation | Manual or automatic (fold failure) |

### 5.2 Automatic Activation

The emergency beacon activates automatically when:
- Fold failure is detected (fold collapse during transit)
- Fold abort is triggered (manual or automatic)
- Life support failure is detected
- Vehicle structural damage is detected
- Communication failure with ground control

### 5.3 Beacon Content

The emergency beacon transmits:
- Vehicle identification (call sign)
- Last known position (GPS coordinates)
- Fold failure code (if applicable)
- Time since last communication
- Passenger count (if known)
- Vehicle status (systems operational/failed)
